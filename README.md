## 怎麼用

1. **寫策略**:從範本開始(均線交叉、EMA + RSI、通道突破、RSI 反彈、布林、MACD、買入持有…),或**自訂**: 自己加參數、指標、進出場規則(規則語法,見下面);也可以切到「**Python 策略**」,用你自己的 Python 程式產生進出場訊號(見「用 Python 寫策略」)。
2. **選標的**:單一標的,或投資組合(最多 8 檔、自訂權重)。**在搜尋框輸入代號或公司名稱就會自動從網路下載資料**(例如 `AAPL`、`2330.TW`、`^GSPC`、`BTC-USD`、`Tesla`),不需要自己找 CSV;這個功能要用 `node tools/serve.mjs site 8080` 啟動網站(見下面)。也可以上傳 CSV(TradingView、Yahoo 匯出都可以)。
3. **執行回測**(或按 Ctrl/⌘ + Enter),看績效、回撤、月報酬、每一筆交易。

另外:策略可以儲存在瀏覽器、匯出/匯入 JSON、或複製**分享連結**(連結內含策略與標的設定,任何人打開就是同一份設定;上傳的資料不會包含在內)。

## 策略語法

規則是一行運算式,結果為真就觸發。收盤後判斷,**下一根開盤成交**。介面左邊的「語法說明」列出全部函式。

```
cross_above(ema(close, 12), ema(close, 26)) and rsi(close, 14) < 70 and close > sma(close, 200)
```

| 項目 | 內容 |
|------|------|
| 價格 | `open high low close volume hl2 hlc3` |
| 歷史值 | `close[1]` 前一根;只能是 0 以上的整數,**不能看未來** |
| 運算 | `+ - * / %`、`< <= > >= == !=`、`and or not`(也可寫 `&& \|\| !`)、鏈式比較 `1 < x < 4` |
| 指標 | `sma ema rma rsi atr highest lowest stdev change shift roc zscore macd macd_signal bb_upper bb_lower` |
| 交叉 | `crossover(a, b)`(= `cross_above`)、`crossunder(a, b)`(= `cross_below`) |
| 其他 | `abs max min`、數字、`true / false` |

- **參數**:數字放在「參數」表,規則裡直接用名稱,改一個地方就好。
- **指標**:由上往下計算,後面的可以引用前面的。
- **止損/止盈**:固定百分比、ATR 倍數,或任何運算式(結果是距離成交價的 %)。
- 暖機期(指標還是空值)不會產生訊號;NaN 的比較一律視為假。

規則解析器是自己寫的(不使用 `eval` / `new Function`),使用者輸入無法執行 JavaScript;長度、巢狀深度、歷史索引都有上限,並有針對這些情況的測試。

## 用 Python 寫策略

策略可以不用規則語法,而是用你自己的 Python 程式。策略編輯器最上方切到「**Python 策略**」,選一個策略就能回測,**輸入代號下載資料後會自動用它回測**。
Python 只負責「什麼時候進出」;成交假設(收盤確認、下一根開盤成交)、止損止盈、投入比例、手續費與滑價、績效指標、圖表都和規則策略共用同一個引擎。

**需求**:Python 3 與 `pip install pandas numpy`。網站要用 `node tools/serve.mjs site 8080` 啟動(Python 在這台本機伺服器上執行,不在瀏覽器裡)。找不到 Python 時,編輯器會說明原因與怎麼修。

**放哪裡**:`strategies_py/` 資料夾(範本 `_template.py`、範例 `example_sma_cross.py`、`example_trend_filter.py`)。存檔後在網站按「重新整理」就會列出來,不用重啟。
你自己的策略檔**預設不會被 git 追蹤**(`.gitignore`),避免把研究中的策略不小心推上公開的 repo。想用你研究專案裡的資料夾:`node tools/serve.mjs site 8080 --strategies /path/to/strategies`(也可以設環境變數 `STRATEGY_LAB_STRATEGIES`);指定 Python:`--python /path/to/python` 或 `STRATEGY_LAB_PYTHON`。

**約定**(一個 `.py` 檔 = 一個策略,檔名去掉 `.py` 是策略 id):

```python
NAME = "我的策略"                       # 選用: 網站上顯示的名稱
PARAMS = {"fast": 12, "slow": 26}      # 選用: 預設參數,網站上變成可以修改的欄位(數字或文字)

def run(df, params):
    # df: pandas.DataFrame,索引是日期(由舊到新、不重複),欄位 open high low close volume(調整後價格)
    # 回傳長度和 df 相同的結果,二選一:
    #   1. 目標部位序列: +1 做多 / 0 空手 / -1 放空
    #   2. dict: entry_long / exit_long / entry_short / exit_short(布林序列),
    #            stop_loss_pct / take_profit_pct(距離成交價的百分比序列,5 = 5%,NaN = 不設)
    ...
```

- **時點**:第 t 根收盤算出的訊號,在第 t+1 根開盤成交(和規則策略相同)。回傳值裡的 NaN = 這根還沒有訊號(指標暖機中),不會交易。
- **部位模式**是「目標」: 空手時目標是多就進場、持有多單時目標不是多就出場(空單同理);止損止盈觸發出場後,如果目標還是多,下一根會再進場。要精確控制「只在穿越那一根進場」請用事件模式。**部位大小會被忽略**(只取 +1 / 0 / -1,並警告);分數權重請用「目標權重」分頁。放空要在網站上勾「允許做空」。
- **偷看未來的檢查(預設開啟)**:Python 拿得到整段歷史,規則語法沒有這個風險,所以網站會把資料截短再重跑(截到倒數第二根,以及最多 6 個「進場訊號為真的那一根」之後),**前面的訊號如果因為後面的資料而改變,就在結果頁警告**(哪一天、哪個訊號、截到第幾根)。選在進場訊號之後截短,是因為偷看未來的策略正是在這些地方靠未來資料才成立;測試裡對 25 組不同資料、三種偷看方式(整段偷看、只有後半偷看、只靠 NaN 的位置偷看)都 100% 抓到,誠實的策略 0 次誤報;沒有任何進出場訊號、只靠止損序列偷看的情形也有測試。常見原因:`shift(-1)`、整段資料的平均 / 最大最小值 / 標準化、`bfill`。有隨機性的策略請固定亂數種子,否則會誤報。少於 100 根不檢查;檢查用的截短重跑失敗時回報「沒有結論」,不當成通過也不當成失敗。
- **除錯**:策略裡的 `print` 會顯示在結果頁(前 3 行);執行出錯會顯示例外與最後幾行 traceback;回傳格式不對會說明哪裡不對(長度、不認得的鍵、inf、非正的止損…)。
- **安全**:策略以你的身分在你的電腦上執行(和你自己在終端機跑 `python` 一樣),**不要放來路不明的檔案**。`/api/py` 只會執行資料夾裡的 `.py`(id 只能是英數字 / 底線 / 連字號)、每次一個獨立子行程、有逾時(預設 120 秒)、同時最多 2 個,並套用和 `/api` 相同的請求檢查(只聽本機、Host 檢查、自訂標頭、POST 必須是 `application/json`)。
- **目前只接在「策略回測」分頁**。「目標權重」與「當沖掃描」仍用規則語法 / JSON 網格;你的研究程式(`lab/` 裡的策略)要接到那兩頁時,把檔案給我,我照同樣的方式(先對照你的 Python 輸出做一致性測試)接上。

**驗證**:同一份資料上,Python 策略與等價的規則策略(`example_sma_cross` ↔ `cross_above(sma(close, 8), sma(close, 25))` 等)產生的**交易逐筆相同**(進出場日、價格、股數、損益、出場原因),涵蓋事件模式、部位模式(含 +1 / -1 做空)、搭配止損止盈 / 倉位比例 / 成本;
瀏覽器裡兩種寫法跑出的績效指標也完全相同。偷看未來的策略會被抓出來,誠實的不會。以上用真的 Python 子行程測試(`tests-js/pyapi.test.js`、`tests/test_py_runner.py`、`tests-js/e2e/python.e2e.test.mjs`),並做過突變測試(故意改壞 39 種做法;第一輪有 8 個沒被擋下,補測試後全部擋下,其中一個是多餘的備援截短位置,已移除)。

## 成交與績效假設

| 項目 | 做法 |
|------|------|
| 訊號時點 | K 棒收盤確認,下一根**開盤**成交;指標只用當根及之前的資料(有「截掉後面資料,前面結果不變」的性質測試) |
| 成本 | 手續費與滑價以 bps 計,進出場各算一次;滑價一律對你不利 |
| 止損 / 止盈 | 用 K 棒的最高/最低判斷;**同一根都碰到取止損**;開盤跳空越過則以開盤價成交;止損含滑價、止盈不含 |
| 部位 | 每個標的同時最多一個部位;每次投入「淨值的 X%」,可以做空,可零股 |
| 投資組合 | 每個標的分到「資金 × 權重」,各自獨立跑策略,權益曲線依日期加總;不再平衡 |
| 買入持有基準 | 同樣的權重與資金,在區間第一根開盤買進、持有到最後 |
| 回測結束時仍持有 | 不強制平倉,以收盤價計入權益,交易明細標為「持有中」 |
| 年化 | 年化係數由資料估計(筆數 ÷ 年數),股票與加密貨幣混在同一個組合也成立;無風險利率 0 |
| 暖機 | 開始日之前的資料仍用來預熱指標 |

引擎與一份獨立實作的 Python 引擎有一致性測試(標準答案固定在 `tests-js/fixtures/`):同一份資料、同一個策略,**33 筆已平倉交易加 1 筆持有中,進出場日、價格、出場原因逐筆相同**。

## 當沖掃描(分頁)

回測分頁看的是「一個策略的權益曲線」。**當沖掃描**看的是另一件事: 每個「標的 × 交易日」是一筆獨立的當日進出交易,沒有持倉延續,
看逐筆統計(勝率、平均每筆淨報酬)以及「多少比例的個股各自都達標」。規則可以是單一一條,或一整個**網格**(條件 × 進場 × 出場 的所有組合)。

### 規則的四個部分

| 部分 | 內容 |
|------|------|
| 方向 | 做多 / 放空 |
| 條件 | 今天開盤時要不要做(一般規則語法,例如 `open / close - 1 <= -atrp`) |
| 進場 | 開盤市價;或限價 = 開盤價往不利方向退一段(距離是運算式,占開盤價的比例) |
| 出場 | 收盤市價;或停利限價(幅度是運算式,占進場價的比例),沒到就收盤出場 |

**開盤決策框架**: 條件與距離都在「今天開盤時」判斷,所以 `open` 是今天的開盤價,`high` / `low` / `close` / `volume` / `hl2` / `hlc3` 和所有指標都是**前一日**的值,`close[1]` 是前二日。
跳空幅度就是 `open / close - 1`,ATR% 是 `sma(tr(), 14) / close`。這是框架本身的設計: 規則寫不出偷看當天高低收的東西(性質測試: 把第 t 天起的高低收與之後的一切換成亂數,第 t 天的條件值不變)。
外部序列(例如 `^VIX`)用前一日的收盤價。

### 成交假設

- 單邊成本預設 5 bps,每筆淨報酬 = 方向 × (出場價 ÷ 進場價 − 1) − 2 × 單邊成本;勝 = 淨報酬 > 0(剛好 0 不算贏)。
- 限價單與停利單必須被穿價(預設 10 bps)才算成交,只碰到不算;成交在限價,不在最低/最高價。
- **日線分不出盤中高低點的先後。** 開盤市價進場時「最高價 ≥ 停利價」一定發生在進場之後,沒有歧義;限價進場時最高價可能在成交**之前**。所以限價進場加停利的規則同時算兩種:
  **保守** = 收盤已經越過停利價才算停利(真實績效的下界,正式數字看這個);**樂觀** = 最高價碰到就算(上界)。連上界都過不了的規則可以直接淘汰;
  反過來,樂觀算法下「全過」的規則多半是假象(在合成資料上也能重現這個現象)。
- 資料品質過濾(用當天的 K 棒): 四價缺值或非正價、最高/最低價與開收價矛盾超過 0.5%、一字線(最高 = 最低)的日子不交易;輕微矛盾修正後照常交易。
- 所有指標都有值的日子才交易(例如 ATR% 要累積 15 根)。

### 驗收與 holdout 紀律

驗收標準可以自己設定,預設是 D1 勝率 > 80%、D2 平均每筆淨報酬 ≥ 1%、D3 > 50% 的個股各自勝率與平均都達標(個股至少 30 筆)。
沒有規則全過時,機械地列出「最接近」的候選: (a) 勝率過門檻者中平均最高、(b) 平均過門檻者中勝率最高、(c) min(勝率 ÷ 門檻, 平均 ÷ 門檻) 最大。另有可行邊界(勝率至少 X 時平均最高能到多少)與規則散佈圖。

**掃描只用開發集**(holdout 起始日以前),holdout 的資料不會被算進去。要看某條規則的 holdout 必須明確按按鈕並確認;系統記錄「這份資料與規則組合的 holdout 看過幾次」(存在你的瀏覽器),
每多看一次證據力就再打折。holdout 結果同時給 保守 / 2 倍成本 / 樂觀 三種。

### 資料來源

- **內建標的**: 勾選多檔(內建清單只有幾十檔,統計意義有限)。
- **上傳 .npz 面板**: 直接讀 numpy 的 `np.savez_compressed` 檔(例如研究程式的 `cache/sp500_daily.npz`),需要 `dates`、`tickers`、`Open`、`High`、`Low`、`Close`(日 × 檔,float32),選用 `vix`。檔案只在瀏覽器裡讀取。
- **上傳多個 CSV**: 每個檔案一檔標的,代號取自檔名。
- 多檔對齊成同一條交易日曆: 每天「在世的標的」裡超過一半有 K 棒的日子才保留,所以股票與加密貨幣混在一起時週末會被剔除(否則每檔股票都會有 NaN,14 日平均永遠算不出來)。

```json
{ "name": "…", "indicators": [{ "name": "atrp", "expr": "sma(tr(), 14) / close" }], "aux": [{ "name": "vix", "ticker": "^VIX" }],
  "setups":  [{ "side": "long", "name": "gap<=-1atr", "expr": "open / close - 1 <= -atrp" }],
  "entries": [{ "name": "open", "expr": "" }, { "name": "lim1atr", "expr": "atrp" }],
  "exits":   [{ "name": "close", "expr": "" }, { "name": "tp1%", "expr": "0.01" }],
  "costBps": 5, "bufferBps": 10 }
```

規則名稱是 `方向|條件|進場|出場`,例如 `long|gap<=-1atr|lim1atr|tp1%`。「載入標準網格」是 14 個條件 × 6 種進場 × 7 種出場 = 588 條,名稱與順序和使用者研究程式的 `grid()` / `name()` 相同,結果可以直接對照。
可以匯出 / 匯入網格 JSON,也可以把全部規則的結果下載成 CSV。掃描在 Web Worker 裡跑(Node 實測: 503 檔 × 約 6,700 個交易日 × 588 條規則,同時算保守與樂觀,約 18 秒)。

### 與使用者的 Python 實作對照

當沖引擎對照使用者研究程式裡的實作(`build_panel` / `load_panel` / `grid` / `trades` / `stats`、`run_daytrade.py` 的 `candidates` / `frontier` / 通過數統計)做了一致性測試:
在亂數合成的面板上(含晚上市、下市、一字線、高低價矛盾、非正價格),**588 條規則 × 開發集 / holdout × 保守 / 樂觀 / 2 倍成本的每一項統計都相同**,候選與可行邊界也相同。
標準答案是用他的程式在 `tests-js/fixtures/daytrade_panel.npz` 上算出來的(他的程式本身不在這個 repo)。已知差異只有一個: 標的**中間缺值**(停牌)時,Python 的指數平滑會按時間衰減權重,這裡跳過缺值,
所以 `rsi()` 在缺值後幾根內可能不同(測試中受影響規則的筆數差不到 1%);沒有中間缺值時完全相同。測試資料是合成行情,**不是真實行情,沒有用真實的 S&P 500 資料驗證過**。

### 盤中 K 線驗證(60 分 / 5 分 K)

日線分不出「限價單成交」和「停利」誰先發生(上面的保守 / 樂觀只是把真值夾在中間)。載入研究程式 `build_intraday()` 產生的盤中檔,就可以用盤中 K 棒把先後解開;
「資料」區塊多了兩個檔案欄位(60 分 K、5 分 K),按「**盤中驗證**」執行。流程照使用者的 `run_daytrade.py --intraday`:

1. **掃描(只用 I1)**: 60 分 K 的交易日對半切,前半 = I1(選擇)、後半 = I2(確認;天數是奇數時 I2 多一天)。對所有規則算 I1 的保守與樂觀(個股最少 5 筆)。
   **存活候選** = I1 樂觀上界仍過 D1 與 D2 的規則(上界都過不了,盤中不可能達標);另外照日線掃描同樣的方式機械決定「候選」(通過 / (a)(b)(c))。
2. **確認(要自己按按鈕)**: 對「存活候選 + 候選」看 I2(保守、樂觀、兩倍成本)與 5 分 K(保守、樂觀,所有交易日,個股最少 1 筆)。
   **合格** = 存活候選,且 I2 保守過 D1–D3、I2 兩倍成本過 D1 與 D2、5 分 K 保守過 D1 與 D2。不合格時會寫出是哪幾項沒過。
   跟 holdout 一樣,系統記錄「這份資料與規則組合的 I2 與 5 分 K 看過幾次」(存在你的瀏覽器),每多看一次證據力就再打折。掃描階段不會算 I2 與 5 分 K(測試: 把 I2 的 K 棒全部改掉,I1 的結果一模一樣)。

**盤中怎麼成交**(`site/js/engine/intraday.js` 檔頭有完整說明): 條件、限價距離、停利幅度仍然用日線(開盤決策框架)算;進場價 E = 當天開盤 × (1 ∓ 距離)。
市價進場成交在開盤;限價進場要等到第 j 根 K 棒的低點(放空是高點)穿過 E 一個緩衝才成交。停利價 T 的判斷從成交之後才開始:
**保守** = 第 j+1 根(含)以後的高 / 低點穿過 T 才算停利(成交那一根不算,因為同一根裡的先後仍分不出來);**樂觀** = 第 j 根(含)以後。沒停利就收盤出場,每筆淨報酬的算法與日線相同。

盤中檔的格式是 `build_intraday()` 的輸出: `dates`(日)、`H` / `L`(日 × 第幾根 × 檔)、`O` / `C`(日 × 檔),float32,缺值是 NaN;選用 `tickers`。
他的檔案**沒有存代號**,所以檔的順序必須和日線面板一致(檔數對不上會在載入時報錯);有 `tickers` 欄位時改用代號對齊。盤中日期不在日線日曆上的日子會被略過(載入時會告訴你幾天)。

**對照使用者的 Python**(`lab/daytrade.py` 的 `load_intraday` / `trades_intraday` / `stats`、`run_daytrade.py` 的 `intraday()`): 在亂數合成的 60 分 K(161 個交易日 × 7 根)與 5 分 K(45 個交易日 × 78 根),
含缺棒、整天缺資料、開 / 收盤缺值與不在日線日曆上的日期,**588 條規則 × I1 / I2 / 5 分 K × 保守 / 樂觀 / 兩倍成本的每一項統計都相同**;
存活候選、候選、通過數、可行邊界、確認階段的每條規則與合格判定也相同(兩組門檻各跑一次: 他的原始門檻,以及放寬後才會有合格規則的門檻)。
標準答案用他的程式在 `tests-js/fixtures/intraday_60m.npz`、`intraday_5m.npz`(搭配 `daytrade_panel.npz`)上算出,存在 `intraday_golden.json`。
另外有手算案例(成交與停利在同一根 K 棒、停利早在成交之前就碰過、最後一根才成交、緩衝剛好等於的邊界、放空鏡像、缺值)與突變測試(故意改壞 60 種做法,全部被測試擋下)。
**合成的盤中資料不是真實行情;沒有用真實的 S&P 500 盤中資料驗證過**(這個環境抓不到 Yahoo 的盤中資料)。Yahoo 的盤中資料有保存期限(60 分 K 約 730 天、5 分 K 約 60 天),樣本期間因此不長。

速度(Node、合成資料實測): 503 檔 × 日線 6,700 天 × 588 條規則,60 分 K(730 個交易日 × 7 根)掃描約 9 秒、5 分 K(60 個交易日 × 78 根)約 6 秒;同樣在 Web Worker 裡跑。

盤中驗證目前沒有「單一規則明細」(逐年、逐檔、報酬分佈)那一頁,只有 I1 / I2 / 5 分 K 的統計列與判定。

## 目標權重(槓桿)分頁

不寫進出場訊號,而是每天收盤算出「每個標的應該占淨值多少」(1 = 滿倉、2 = 2 倍槓桿、0 = 空手、-1 = 放空一倍),隔天開盤調整。
適合波動管理、波動目標、趨勢濾網加槓桿、雙動能輪動這類策略。權重是一般的規則運算式,可以引用任何資料序列(`spy_close`、`oil_close`…)。

**帳戶慣例**(全部寫在 `site/js/engine/weightsrun.js` 的檔頭,因為每一條都會影響績效):

- 訊號: 第 t 天收盤的目標權重,第 t+1 天開盤成交。目標權重先把 NaN / 無限大當 0、不能放空時夾到 ≥ 0、總曝險超過上限時等比例縮小。
- **再平衡帶**: 某標的開盤時的實際權重與目標相差「超過」帶(預設 10%)才調整到目標,一次成交算一筆;帶內的偏離不動。成本 = 成交金額 × 單邊 bps。
- **利息**每根 K 棒結算: 日曆天數 ÷ 365,依**前一根收盤**的餘額。閒置自有現金(淨值 − 多單市值)賺利率;多單市值超過淨值的部分(融資)付「利率 + 融資利差」;空單市值付借券費;放空所得不計息、也不拿來抵融資。利率可以是固定值或利率序列(例如 `^IRX` ÷ 100)。
- 不模擬追繳保證金: 淨值 ≤ 0 就視為爆倉,部位清空、淨值歸零並維持到結束。
- 「策略從資料開頭就開始跑,只取開始日之後的績效」(預設): 開始日只是績效從哪天起算,部位是延續下來的,等於「凍結的規則在那段期間的表現」;不勾則在開始日當天空手重新開始。

規則語法在這一版多了 `std`(樣本標準差)、`ret`、`sum`、`cummean`、`sqrt`、`log`、`exp`、`sign`、`pow`、`clip`、`ifelse`、`avg`。範本裡標「依描述實作」的,是依研究筆記的文字描述寫成。

### 在真實資料上重現研究筆記的數字

研究筆記(實驗室 README)記載了幾個規則在 holdout 期間的真實結果。`tools/reproduce_notes.mjs` 用真實的 Yahoo 價格,把筆記描述的規則跑一遍並並排印出來。

| 規則與期間 | 這裡(CAGR / Sharpe / 最大回撤) | 筆記 |
|---|---|---|
| GOOG 波動管理,2022-04-29 → 2026-10-07 | 30.1% / 0.94 / −31.6% | 30.8% / 0.94 / −31.6% |
| QQQ 波動管理 + 200 日線閘門,2021-03-30 → 2026-10-07 | 22.8% / 1.00 / −31.9% | 22.9% / 1.00 / −31.9% |
| AMAT 套用同一個規則,2021-05-28 → 2026-10-08 | 30.8% / 0.80 / −51.1% | 30.6% / 0.80 / −51.1% |

CAGR 差 0.1 ~ 0.7 個百分點(期間第一天的損益是否計入會差約這麼多;上表計入),夏普與最大回撤幾乎相同。平均曝險(1.11× / 1.19× / 1.08×)與筆記描述的(約 1.11× / 1.2× / 1.08×)一致;使用融資的日子占比(61% / 63% / 47%)與筆記的(63–73% / 約 62% / 42–48%)大致一致,GOOG 略低一點。

## 資料是真實的嗎?怎麼驗證

網站本身沒有任何寫死或模擬的行情。內建資料只有一個來源: 部署流程(或你在自己的電腦上執行 `tools/fetch_prices.py`)從 Yahoo Finance 抓下來的日線,頁尾會顯示來源與更新時間。
合成資料只存在測試與截圖裡(名稱都標明「合成測試資料」),不會進入網站。

「抓到的資料是不是對的」用獨立來源交叉驗證(`tools/verify_prices.py`,Actions 的 `verify-data` workflow 手動執行、唯讀):
美股與 ETF 對 Nasdaq 公布的原始價格、`^VIX` 對 CBOE、`^IRX` 對美國財政部 3 個月期殖利率。比較每天的「日內報酬」C/O−1 與「振幅」H/L−1
(調整後價格是把開高低收乘上同一個係數,所以這兩個比值不受股利調整影響),以及最近 3 天收盤價的水準。2026-10-29 的結果(各 500 個交易日):

- 23 檔美股與 ETF 全部通過: 日內報酬相關係數 0.9998 ~ 1.0000,差的中位數 ≤ 0.0003%,最近收盤價水準差 0.00%。

- **沒有獨立來源可比對、所以只有資料品質閘門把關的**: 台股(0050、0056、2330、2317、2454)、加密貨幣、`^SOX`、原油期貨 `CL=F`。台股有 6~11% 的 K 棒開收價相同,頁面上會標警告;2412.TW 因為 29% 而被排除。

來源取不到資料時驗證工具結束碼是 2(不是通過)。Stooq 與 FRED 從 GitHub 的 runner 連不到,所以沒有用。

## 價格資料

- **內建資料**:`tools/fetch_prices.py` 從 Yahoo 抓日線,存成**調整後價格**(股利、分割),預設抓 26 年(約 2000 年起)。要增減標的改 `tools/universe.json`。
- **資料品質閘門**:Yahoo 的外匯日線有大量收盤價被填成開盤價(實測約 60% 的 K 棒),這種資料回測出來的結果是假的。所以:
  開收價「完全相同」但有振幅的 K 棒占比 > 25% 的標的直接**排除**;5%~25% 的收錄但在介面上警告;K 棒不足 250 根的排除;今天尚未收盤的 K 棒一律丟掉;通過的標的不到一半時整個流程失敗,**保留上一版網站**而不是發布空的。
  因此內建清單沒有外匯。要回測外匯,請上傳 TradingView 匯出的 CSV(上傳時同樣會檢查並警告)。
- **輸入代號自動下載**:網站由 `node tools/serve.mjs` 提供時,標的選擇器的搜尋框可以輸入代號(按 Enter)或名稱(點搜尋結果)。瀏覽器不能直接呼叫 Yahoo(跨網域限制),所以由這台**只聽 127.0.0.1** 的本機伺服器代抓(`/api/search`、`/api/prices`,見 `tools/api.mjs`)。
  - 清理與品質閘門和內建資料**同一套**:`tools/yahoo.mjs` 是 `tools/fetch_prices.py` 的逐行移植(調整後價格、丟空值與非正價格、修正高低價矛盾、丟掉當地「今天」的 K 棒、同一天多筆只留最後一筆;開收價相同但有振幅的 K 棒 > 25% 就**拒絕並說明原因**,5%~25% 收錄並警告)。兩個差別:使用者自己輸入的標的最少只要 30 根(不是 250 根;少於 250 根會警告),下載後才知道的警告會顯示在標的旁邊。
  - 抓下來的資料存在你的瀏覽器(IndexedDB),重新整理還在;每一列有「更新」(重新下載最新資料,略過伺服器快取)與「刪除」。三個分頁共用同一份清單。伺服器端快取 6 小時,對 Yahoo 的請求一次一個、間隔 0.3 秒。
  - **沒有 `/api` 的環境(純靜態託管)**:網站偵測不到就不顯示下載功能,輸入找不到的標的時會說明要用 `node tools/serve.mjs site 8080` 啟動,仍然可以上傳 CSV。
  - 安全:只接受 GET;Host 必須是 127.0.0.1 / localhost(防 DNS rebinding);必須帶自訂標頭 `X-Strategy-Lab`(別的網站的跨網域請求會被瀏覽器的預檢擋下,這裡不回應預檢);代號只接受 `A-Za-z0-9^.=-`、最長 20 字;只會連到固定的 Yahoo 主機。
  - 搜尋:可以輸入英文名稱(`apple`、`taiwan semiconductor`)或代號(`2330` 會找到 `2330.TW`);**Yahoo 的搜尋不支援中文名稱**(實測對任何中文都回 400),輸入中文時網站會直接說明,不會送出請求。
  - **在真實 Yahoo 上驗證過**(GitHub Actions 的 `live-fetch-check`,因為沙箱連不到 Yahoo):`SPY`、`AAPL`、`^GSPC`、`BTC-USD`、`2330.TW`、`CL=F`、`EURUSD=X`、`^VIX`、`GOOG` 九個代號,把 Yahoo 的**同一份原始回應**分別交給 Python 版與 Node 版清理,**序列與品質判定完全相同**;
    真的伺服器的 `/api/search`、`/api/prices`、找不到代號的 404 都符合預期;真的 Chromium 開網站,搜尋 → 下載 → 回測 → 四檔不同日曆的組合 → 重新整理後資料還在,沒有 console 錯誤。
    一個意外的發現: **Yahoo 對同一個代號連續兩次請求,回傳的 `adjclose` 會有浮點雜訊**(GOOG 約 3,700 個數字相差 5e-7 以內),清理成 6 位有效數字後有約 570 個價格差在最後一位(相對差 ≤ 1e-5);日期與成交量完全相同,開高低收的原始值也完全相同。對回測沒有實質影響,但代表**兩次下載的數字不會逐位相同**(內建資料也一樣)。
  - 限制:資料來源是 Yahoo 的**非官方** API,可能被限流或改版;台股要加 `.TW`、港股 `.HK`;**分享連結不含下載的標的**(和上傳的 CSV 一樣,對方要自己下載);Yahoo 的外匯日線品質差,會被品質閘門拒絕。
- **上傳 CSV**:需要 `time`(或 date)、`open`、`high`、`low`、`close` 欄位;支援 unix 時間、ISO 日期、分號/Tab 分隔、`Adj Close`;會自動排序、去重、修正高低價矛盾,並顯示處理了幾列。檔案只存在你的瀏覽器(IndexedDB)。

## 已知限制

- 回測與目標權重是日線;當沖掃描預設也用日線(保守 / 樂觀兩種算法夾住),要解開限價成交與停利的先後需要自己載入盤中檔(見上面「盤中 K 線驗證」)。
- 盤中驗證: 沒有逐條規則的明細頁;I2 / 5 分 K 的「只看一次」是瀏覽器裡的紀錄,清掉網站資料就歸零,靠自律而不是強制。
- 「策略回測」分頁: 一個標的同時一個部位,不能加碼或分批;不計融資利息與強制平倉(要這些請用「目標權重」分頁,但它同樣不模擬追繳保證金)。
- 目標權重: 利息依日曆天數 ÷ 365 與前一根收盤餘額結算;放空所得不計息也不抵融資;借券費是固定年率(壓力期的借券費飆升與無券可借不在模擬內)。
- 台股的證交稅等要自己換算成 bps 填進成本欄位。
- 內建資料與「輸入代號自動下載」都來自 Yahoo 的非官方 API,可能被限流或改版;內建資料失敗時 workflow 會變紅並保留上一版網站,自動下載失敗時會直接顯示原因。
- 回測是歷史模擬,不代表未來績效。
